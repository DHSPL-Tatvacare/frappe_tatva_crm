# UI.md — UI constitution (frappe_tatva_crm fork)

Non-negotiable rules for every frontend change in this fork. Hard-won; breaking the
letter is breaking the spirit. (Architecture/backend invariants live in the
`frappe_tatva_connect` `CLAUDE.md`; this file is UI only. See `CLAUDE.md` here for how
this fork connects to `tatva_connect`.)

1. **Reuse native primitives — reinvention is a defect.** Find the frappe-ui / CRM-fork primitive first (`ListView` family, `EmptyState`, `FormControl`, `Popover`, `Dialog`, `Filter`/`SortBy`/`ColumnSettings`, `useActiveTabManager`, `formatDate`) and use it. A parallel implementation of something native is a defect.
2. **Build on the EXISTING lifecycle/state path — don't invent a parallel one.** Same Pinia setup-stores, same `createResource` data layer, same router patterns. Invent *on top of*, never beside.
3. **Mount lifecycle & 1× API.** `router-view` is keyed on `$route.fullPath`, so any path change remounts the page. So: never `router.replace`/redirect on mount; never pair `auto:true` with a `watch→reload()` (double-fetch); one `createResource` per mounted component. Verify the call count is 1× in the network panel before claiming done.
4. **Bind to `resource.data` — never copy into refs in `onSuccess`.** A `cache`-keyed resource serves cache hits *without* firing `onSuccess`, so copied refs go stale. Expose rows/columns/total as `computed` off the resource.
5. **Empty / loading / error = the native `EmptyState` in a FULL-HEIGHT container.** Never a bare centered line, never a fixed `min-h`. The whole chain (`flex flex-1 flex-col` / `h-full`) carries height down so it centers.
6. **Lay out with CSS, not JavaScript.** Flexbox (`flex-1 basis-0 min-w-0` to share+truncate, `shrink-0` for pinned). No `ResizeObserver`/`offsetWidth` measuring. The element that must flex must BE the flex child. (Sole JS exception: soft-keyboard insets — see §24.)
7. **Theme-aware tokens, and know which is which.** `ink-*` is text-only (`border-ink-*` renders light gray). For a theme-flipping surface/line use `surface-*`. Verify the computed color in BOTH themes. Never hardcode hex (except a documented brand value).
8. **Never gate a tab/layout on a value you blank-then-resolve.** Toggling an async boolean false→true makes the gated element vanish→reappear and resets native tab managers. Memoize the decision per key; keep the previous value until the real answer lands.
9. **PWA stale-cache discipline — MANDATORY before every verification.** After every `bench build`: unregister the service worker, clear `caches`, navigate away+back. Confirm the live DOM has your new classes (computed style), not just a screenshot.
10. **Verify with evidence, not belief.** Every UI claim needs fresh proof from THIS build: post-cache-bust screenshot, network call count, and/or computed style. No "should work."
11. **Header-less requests (`sendBeacon`, beacons, raw form posts) MUST carry `csrf_token` in the body.** Frappe requires CSRF on every authenticated POST; `sendBeacon` can't set the header, so put `csrf_token: window.csrf_token` in the JSON body or it 500s.
12. **Reuse a doctype-coupled native control over custom data with a GUARDED `fields` prop — never fork its logic.** Add ONE optional `fields`/`fieldSource` prop (marked `// TATVA:`) that replaces the meta fetch when non-empty and is 100% stock when absent. Building a parallel filter/column/sort UI is a defect.
13. **Don't put popover-based controls inside a modal — build an INLINE control.** `Filter`/`SortBy`/`ColumnSettings` (any frappe-ui `Popover`) teleport outside the dialog panel and fire `interact-outside` (closing the dialog). Popover controls are for a list toolbar; in a modal render the UI inline.
14. **One remount source only — never stack `:key`s.** `App.vue` already keys `<router-view>` on `$route.fullPath`. An extra `:key` on a child double-mounts → double fetch. Let the page remount be the single refresh trigger.
15. **Reuse native when it fits; otherwise build a NEW GENERIC component on the native lifecycle.** Where native UX is wrong for the context, build a new **generic, prop-driven** component (no hardcoded fields/doctype) on frappe-ui controls + `createResource`, in `tatva/`, named generically. Building new ≠ reinventing.
16. **Match the native toolbar shape: ONE horizontal row, controls right-aligned.** Never `flex-wrap` a toolbar (it stacks vertically). Search left; Filter/Sort/Columns + an Edit affordance in an `ml-auto flex items-center gap-2` group. Don't repeat the record count.
17. **Tight, flat DOM — frappe-ui `Button` and `Dialog#actions` are chunky.** For a tight in-row control use a plain `<button>` + small `FeatherIcon`. The Dialog `#actions` slot adds a dead ~40px band; for a tight footer render inside `#body-content`. Two-panel/builder layouts MUST stack on mobile.
18. **frappe-ui `ListView` cannot freeze/pin columns.** It's a CSS grid with no sticky hook, and frappe-ui is an upstream npm package. Skip pinning unless explicitly scoped; keep the column model a plain ordered list.
19. **MOBILE-FRIENDLY IS NON-NEGOTIABLE — CODE RED.** Field reps are mobile-first; a desktop-only change is a regression, not a half-feature. Verify at **~390px on EVERY UI change** (post-cache-bust). Recurring fixes: a `truncate` child that won't shrink ⇒ **`min-w-0`** on the row AND the grid/flex cell; an overflowing chip row ⇒ **`flex-wrap gap-2`**; padding/gap ⇒ match the native timeline (`px-3 sm:px-10`, `gap-2 sm:gap-4`); a scroll-strip that resets on remount ⇒ **`scrollIntoView({inline:'nearest'})`**. The native **Calls/Comments timeline** is the reference for mobile-correct.
20. **ONE bottom-sheet behaviour — content-fit, never fixed-height.** A modal sheet sizes to its content (`max-h-[90dvh]`, `height:auto`); the body scrolls only past the cap. A FIXED height + capped content = a dead white band at the bottom (the bug we shipped). Drag-to-dismiss is GPU `translateY`, not animating `height`. **No "resizable panel vs modal" variants** — every overlay sheet behaves identically (`tatva/TatvaBottomSheet`). The drag handle is handle-scoped, so content gestures (maps, editors) don't fight it.
21. **Teleported popovers vs custom overlays — own the z-index, don't fight per-control.** reka-ui teleports popover/menu content (DatePicker calendar, Link/Select combobox, Dropdown) to `<body>` with `z-index:auto`; an overlay with an explicit `z` (our sheet `z-50`) covers them and the calendar opens *behind* it. Raise `[data-reka-popper-content-wrapper]` above the overlay with ONE rule, scoped by a **media query** to the viewport where the overlay exists — never a per-control patch.
22. **Mobile sheets adopt via the `ResponsiveDialog` wrapper — desktop stays the stock `Dialog`.** Adopting a modal is a tag swap (`<Dialog>` → `<ResponsiveDialog>`), same slots. The wrapper renders the centered `Dialog` on desktop and a `TatvaBottomSheet` on mobile, and MUST forward **`$attrs`** (so a modal's `@close` still fires) and **every slot** (`#body-title`/`#body-header` → sticky header, `#body-content`/`#body` → body, `#actions` → sticky footer). Desktop must stay byte-for-byte stock.
23. **A modal/sheet can MOUNT already-open — sync state with `{ immediate: true }`.** `v-if`-rendered modals (and same-tick opens) mount with the open value already `true`, so a non-immediate `watch(open)` never fires and scroll-lock / keyboard / listeners silently never wire. Always make the open-state watcher immediate.
24. **Soft keyboard: lift a `fixed bottom-0` sheet with `visualViewport`.** On mobile the keyboard sits over a bottom-anchored sheet and hides the focused field. Use `visualViewport` to inset the sheet by the keyboard height, cap it to the visible area, and `scrollIntoView` the focused field. Pure progressive enhancement — no-op where `visualViewport` is absent. (The one sanctioned JS-for-layout exception to §6.)
25. **No DOM hijacks; prefer CSS scoping over JS DOM toggles.** No `MutationObserver`, `innerHTML`, `eval`, or `v-html` to reach into other components' DOM. Standard `document.body.style.overflow` scroll-lock and native `scrollIntoView` (read + scroll, reverted on unmount) are fine. When scoping a global style (e.g. the popover z-index), reach for a **CSS media query before a JS-toggled body class**.
26. **Cross-surface logic uses the ONE shared brain — never a second copy.** A rule that appears on more than one surface (e.g. the user's entitled grain: single → auto-apply, manager → picker) lives in one shared composable/endpoint that every surface imports — same source as the existing surface, never a lookalike. The UI control is thin; the brain (in `tatva_connect`) is shared.
